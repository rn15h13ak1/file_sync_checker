# file_sync_checker

複数拠点の共有フォルダの内容が一致しているかを **SHA-256 ハッシュで突き合わせる** CLI ツール。

拠点ごとにコピーして運用しているフォルダが、いつの間にか食い違っていないかを確認します。
ファイル単位で「同じ / 内容が違う / 片方に無い / 読めなかった」を判定し、
Excel と HTML のレポートにまとめます。**検出のみで、修正は行いません。**

## 主要機能

- **N 拠点の同時比較**: 2 拠点以上に対応。「欠落」と「一部のみ存在」を過半数基準で区別する
- **読み取り量の削減**: サイズ・更新日時から結論が出るファイルを読み飛ばせる（`hash_mode: smart`）
- **日本語ファイル名に対応**: macOS (NFD) と Windows (NFC) の表記揺れを同一ファイルとして扱う
- **原因を追えるレポート**: 行をクリックすると拠点ごとのフルパスとハッシュを表示。パスはコピー可能
- **実行条件を記録**: どのハッシュ方式・除外パターンで照合したかをレポートに残す
- **対話メニュー**: CLI オプションを覚えなくても、番号を選ぶだけで実行できる

## 使い方ガイド

### 1. メニューから実行する

CLI オプションを覚えなくても、番号を選ぶだけで実行できます。

```cmd
:: Windows はこれをダブルクリック
menu.bat
```

```bash
# コマンドから起動する場合
python3 menu.py
```

```
============================================================
  ファイル同期チェック
============================================================
  比較対象: 本社 / 大阪支店 / 名古屋支店 (3 拠点)

============================================================
  実行内容を選択
============================================================
  1. チェックを実行 ― 設定ファイルのとおりに照合する
  2. 条件を選んで実行 ― ハッシュ方式・出力形式・再試行回数を選ぶ
  3. 設定を確認 ― 比較する拠点・除外パターン・出力先を表示する
  4. 前回のレポートを開く ― 出力先にある最新のレポートを開く
------------------------------------------------------------
  0. 終了
============================================================
```

| 操作 | 内容 |
| --- | --- |
| チェックを実行 | 設定ファイルのとおりに照合する |
| 条件を選んで実行 | ハッシュ方式・出力形式・再試行回数をその場で選ぶ |
| 設定を確認 | 比較する拠点・除外パターン・出力先・照合条件を表示する |
| 前回のレポートを開く | 出力先にある最新のレポートを OS の既定アプリで開く |

- **見出しに比較対象の拠点名が出ます**。設定の取り違えに実行前に気付けます
- 実行後は終了コードを意味付きで表示します（例: `終了コード: 1 (差分を検出)`）
- 設定を切り替える場合は `python3 menu.py --config other.yaml`

入力値は `~/.file_sync_checker_menu.json` に記憶され、次回の既定値になります。

> 無人実行（cron・タスクスケジューラ）ではメニューではなく `main.py` を直接呼んでください。

### 2. コマンドから実行する

```bash
python3 main.py                    # 既定で config.yaml を使用
python3 main.py -c path/to/cfg.yml # 設定ファイル指定
python3 main.py -v                 # 詳細ログ
```

設定ファイルを書き換えずに上書きしたい項目はコマンドラインから指定できます（CI 向け）。
一覧は [CLI オプション一覧](#cli-オプション一覧)にあります。

```bash
python3 main.py --format html --hash-mode smart -o ./ci-reports
```

CWD に依存せずフルパスで起動することもできます:

```bash
python3 /full/path/to/main.py -c /full/path/to/config.yaml
```

**パスの解決ルール**

- `-c` 省略時の既定 `config.yaml` は **CWD → main.py と同じディレクトリ** の順で探索します
- `config.yaml` 内の相対パス（`locations[].path`, `output.output_dir`）は
  **config ファイルのあるディレクトリ** からの相対として解決されます。絶対パスはそのままです
- `-o` で指定した出力先だけは **CWD からの相対**です（コマンドラインに書いたパスは
  打った場所から見た相対と考えるのが自然なため）

レポートは `<output_dir>/sync-check-YYYYMMDD-HHMMSS.{xlsx,html}` に出力されます。
HTML 出力時は併せて `<output_dir>/sync-check.html`（タイムスタンプ無し・実行毎に差し替え）も
生成されるため、ブックマークや自動化スクリプトから常に最新レポートを参照できます。

### 3. 照合の厳密さを選ぶ

スキャンは 2 フェーズで動きます。

1. **列挙フェーズ** — 各拠点を再帰列挙し、サイズと更新日時だけを集める（中身は読まない）。
   拠点ごとに並列実行します。Windows では列挙時にサイズ・更新日時が同時に返るため、
   SMB 共有でもこのフェーズはほぼ無コストです。
   大きい共有では列挙だけで時間がかかるため、走査したエントリ数を進捗表示します
   （拠点をまたいで 1 本のカウンタにまとめます）。
2. **ハッシュフェーズ** — 必要なファイルだけを読んで SHA-256 を計算する。
   スレッドプールは拠点をまたいで 1 つだけ使い、全拠点のネットワーク帯域を同時に使います。

`hash_mode` はフェーズ 2 の対象を決めます。

| モード | 動作 | 用途 |
|---|---|---|
| `always`（既定） | 全ファイルを読む | 更新日時を信用しない厳密な照合 |
| `smart` | サイズ相違（内容相違が確定）と、全拠点でサイズ・更新日時が一致するファイルを読まない | ネットワーク共有での日常チェック |

`smart` では読み取り量が大きく減ります（実測: 1,500 ファイル / 1.5GB・差分 25 件のケースで
読み取り対象 1,500 → 75 ファイル、0.70 秒 → 0.04 秒。検出結果は `always` と同一）。

ただし `smart` は更新日時に基づく推定です。**サイズを保ったまま書き換えられ、更新日時も
元に戻されたファイルは検出できません。** 監査用途など取りこぼしが許されない場合は
`always` を使ってください。ハッシュを省略したファイルはレポート上 `(未計算)` と表示され、
サイズ相違による不一致ではサイズ列が強調されます。


| コード | 意味 |
|---|---|
| 0 | 全拠点一致・エラーなし |
| 1 | 差分を検出（スキャン自体は完走） |
| 2 | 設定エラー |
| 3 | 読み取りエラーあり（スキャンが不完全。差分の有無を問わずこちらが優先） |
| 4 | 予期しないエラー（レポート生成失敗など。詳細はログのトレースバック） |
| 130 | ユーザ中断 (Ctrl+C) |

読み取りエラーがあると差分 0 件でも「一致していた」とは言えないため、`1` と `3` を
分けています。「差分・エラーのいずれか」を検知したいだけなら `終了コード != 0` で判定してください。

### 4. 除外パターンを書く

`exclude_patterns` の各パターンは、`/` を含むかどうかで照合対象が変わります。

| パターン | 照合対象 | 例 |
|---|---|---|
| `/` を含まない | ファイル名・ディレクトリ名（深さを問わない） | `*.tmp`, `~$*`, `Thumbs.db` |
| `/` を含む | ルートからの相対パス全体 | `作業中/*`, `a/一時/*`, `*/資料.docx` |

ディレクトリにパターンが当たった場合は、その配下ごと走査しません。


### 5. 定期実行する

cron やタスクスケジューラから実行する場合は、メニューではなく `main.py` を直接呼びます。

```bash
python3 /full/path/to/main.py -c /full/path/to/config.yaml
```

- **進捗バーは自動的に無効になります。** stderr が端末でなければ表示しないため、
  `--no-progress` を付ける必要はありません（付けないと進捗バーの更新がそのまま
  ログに書き込まれ、実測では 10 秒のスキャンで stderr の 97% が制御文字の断片でした）
- **終了コードで結果を判定できます。** 差分（`1`）と読み取りエラー（`3`）は区別されます
  → [Exit code](#exit-code)
- **ネットワークの瞬断には `--retry` が有効です。** Office が一時的に開いているファイルなど、
  すぐ解消する失敗を吸収します。失敗したファイルだけを 0.5 秒 → 1.0 秒…と間隔を空けて
  再試行します。既定は `0`（再試行しない）
- **レポートが溜まり続けないよう `output.keep_reports` を設定してください**
  → [古いレポートの整理](#古いレポートの整理)

```bash
# 毎朝 7 時に実行し、差分かエラーがあれば通知する例
python3 /opt/file_sync_checker/main.py -c /opt/file_sync_checker/config.yaml --retry 2 \
  || echo "同期チェックで問題を検出しました (exit $?)" | mail -s "同期チェック" ops@example.com
```

## 設定ファイル

`config.example.yaml` を参照。主な項目：

- `locations`: 比較対象の拠点（2件以上）
- `exclude_patterns`: glob 除外。`/` を含まなければファイル名・ディレクトリ名、含めば相対パス全体と照合
- `matching.normalize_unicode`: ファイル名を NFC 正規化して突き合わせる（既定 `true`）
- `matching.case_sensitive`: ファイル名の大文字小文字を区別する（既定 `true`）
- `output.format`: `excel` / `html` / `both`
- `output.output_dir`: レポート出力先
- `output.max_table_rows`: HTML の 1 表あたりの最大行数（既定 `20000`、`0` で無制限）
- `output.keep_reports`: 残す過去レポートの実行回数（既定 `0` = 削除しない）
- `performance.parallel_workers`: ハッシュ並列計算スレッド数
- `performance.hash_algorithm`: 現状 `sha256` のみ
- `performance.hash_mode`: `always`（既定）/ `smart`
- `performance.mtime_tolerance_sec`: `smart` で更新日時を一致とみなす許容誤差（既定 2 秒）

## CLI オプション一覧

| オプション | 既定 | 説明 |
| --- | --- | --- |
| `-c, --config PATH` | `./config.yaml` | 設定ファイルのパス |
| `-v, --verbose` | off | 詳細ログを出力する |
| `--no-progress` | off | 進捗バーを無効化する（端末以外では指定しなくても無効） |
| `--format {excel,html,both}` | 設定の値 | `output.format` を上書きする |
| `-o, --output-dir DIR` | 設定の値 | `output.output_dir` を上書きする（CWD からの相対） |
| `--hash-mode {always,smart}` | 設定の値 | `performance.hash_mode` を上書きする |
| `--retry N` | `0` | 読み取りに失敗したファイルを N 回まで再試行する |

`--retry` だけは設定ファイルに項目がありません。環境の一時的な不調に対する指定で、
照合の結果そのものを変えないためです。

## ファイル名の突き合わせ

拠点間で同じファイルかどうかは、OS が返すファイル名をそのまま比較すると誤判定します。

- **Unicode 正規化**: macOS (HFS+/APFS) は「が」を「か」+ 濁点（NFD）で返し、Windows は
  合成済み（NFC）で返します。日本語ファイル名では頻出し、正規化しないと**同じファイルが
  「欠落」と「余分なファイル」の両方に計上されます**。既定で NFC に正規化します。
- **大文字小文字**: Windows 共有は区別せず、Linux は区別します。既定は区別する
  （`Report.docx` と `report.docx` は別ファイル）。同一視したい場合は
  `matching.case_sensitive: false`。

正規化はあくまで**照合キー**にだけ使い、実際にファイルを開くときは各拠点での元のファイル名を
使います（Linux では正規化形が違うと開けないため）。レポートのパスコピーも拠点ごとの
実際の名前になります。同一拠点内で照合キーが衝突した場合（例: `case_sensitive: false` で
`Report.docx` と `report.docx` が同居）は、先に見つかった方を採用してエラーに記録します。

## 出力レポート構成

| シート / セクション | 内容 |
|---|---|
| サマリー | 実行日時・**実行条件**・拠点別ファイル数/サイズ・差分件数 |
| 全ファイル一覧 | 和集合。1行 = 1相対パス、各拠点のサイズ/ハッシュ/更新日時を横並び |
| ハッシュ不一致 | 同名ファイルだが内容が異なる |
| ファイル欠落 | 一部の拠点に存在しない（多数派には存在） |
| 余分なファイル | 一部の拠点のみに存在 |
| エラー対象ファイル | いずれかの拠点で読み取りに失敗（欠落と区別する） |
| フォルダ構造差分 | 拠点ごとにフォルダの有無が異なる |
| エラー | 読み取り失敗・アクセス不可の一覧（拠点・パス・メッセージ） |

### 大きいレポートの扱い

行数が多すぎると、HTML レポートはブラウザで開けなくなります。実測値です（3拠点）。

| 行数 | ファイル | DOMノード | ロード | 判定 |
|---|---|---|---|---|
| 5,000 | 5.6 MB | 75,000 | 0.7 秒 | 快適 |
| 20,000 | 22.4 MB | 300,000 | 1.1 秒 | 実用範囲 |
| 50,000 | 56.0 MB | 750,000 | **30 秒以上無応答** | 使用不能 |

そのため HTML の各表には行数の上限があります。**設定に書かなければ 20,000 行**です
（実測で操作可能を確認できた最大値。既に配布済みの `config.yaml` でも巨大なレポートが
開けなくなる事態を避けるため、既定値を持たせています）。

```yaml
output:
  max_table_rows: 20000   # 0 で無制限
```

- 上限を超えた分は表示せず、表の末尾に省略件数を注記します
- **Excel には全件が出力されます**（上限は HTML だけに適用）
- 上限は「全ファイル一覧」だけでなく各差分セクションにも適用されます
  （フォルダ移動などで差分自体が数万件になることがあるため）
- メールで送るなど軽さを優先する場合は `5000` 程度が扱いやすいサイズです

### 古いレポートの整理

定期実行するとレポートが際限なく溜まります（大きい共有だと 1 回あたり HTML 22MB +
Excel 3MB。毎日実行すれば年間 9GB 規模）。

```yaml
output:
  keep_reports: 30   # 直近30回分だけ残す（0 = 削除しない）
```

**既定は `0`（削除しない）** です。削除は元に戻せないため、明示的に指定したときだけ
動きます。設定に書かなければ従来どおり何も削除しません。

削除は新しいレポートを書き終えた後に実行され、次の条件をすべて満たすファイルだけが
対象になります。

- ファイル名が `sync-check-YYYYMMDD-HHMMSS.{html,xlsx}` に**完全一致**する
- 出力ディレクトリ直下の通常ファイル

したがって、固定名の `sync-check.html`（最新への安定リンク）や、出力先に置いた
無関係なファイル・サブフォルダは削除されません。1 回の実行が html と xlsx の両方を
出していれば、それらで 1 回分と数えます。削除に失敗しても実行自体は成功します
（レポートは既に書けており、後片付けの失敗で終了コードは変えません）。

### 実行条件の記録

レポートのサマリーには、その結果がどういう条件で得られたかを記録します。
設定ファイルのパスだけでは、読み手が保証の程度を判断できないためです。

- **ハッシュ方式** — `sha256 / always（全ファイルの内容を読んで照合）` など
- **ハッシュ省略件数** — `smart` で読み取りを省略したファイル数
- **更新日時の許容誤差** — `smart` のときのみ
- **除外パターン** — 検査対象外だったファイルがあることが分かる
- **読み取り再試行** — `--retry` を指定したときのみ
- **ファイル名の照合** — NFC 正規化の有無、大文字小文字の区別

`--hash-mode smart` のように CLI で上書きして実行した場合も、実際に使われた値が出ます。

### 表示の工夫

- 状態列を色分け（OK=緑 / 不一致=赤 / 欠落=オレンジ / 一部のみ=黄）
- ハッシュ値はセル幅で短縮表示、セル選択（Excel）/ ホバー（HTML）でフル値確認可能
- 欠落セルは「－」灰色背景
- 1行目固定 + 相対パス列固定（横スクロール対応）
- HTML は各表にパス絞り込み・状態絞り込みを用意（表示件数を「100 / 1,000 件」と表示）
- HTML は行クリックで拠点別のフルパス・ハッシュをモーダル表示（パスはコピー可能）

## 既知の制約

- **本ツールは検出のみです。** 修正・反映は人間が判断して実施してください。
- **`hash_mode: smart` は更新日時に基づく推定です。** サイズを保ったまま書き換えられ、
  更新日時も元に戻されたファイルは検出できません。厳密さが必要なら `always` を使ってください。
- **1 つの設定ファイルで比較できるのは 1 組の拠点だけです。** 複数の比較を回す場合は
  設定ファイルを分け、それぞれ `-c` で指定して実行してください。
- **HTML レポートの表には行数の上限があります**（既定 20,000 行）。超えた分は表示されません。
  全件は Excel 側に出力されます → [大きいレポートの扱い](#大きいレポートの扱い)
- **シンボリックリンクは配下に降りません。** リンク先がディレクトリの場合、
  ディレクトリとしては記録しますが中身は走査しません。
- **途中で中断すると、そこまでのレポートは出力されません。** 再実行してください。

## テスト

```bash
pip install -r requirements-dev.txt
pytest          # 328 テストケース
pytest -v       # 詳細出力
pytest -k mino  # 特定の名前のテストだけ
```

権限・シンボリックリンク・大小文字の区別を使うテストは、環境によって成立しないと
skip されます。**root コンテナの CI では権限まわりのテストがまとめて消えても緑になる**ため、
CI では次を立てて skip を失敗として扱ってください:

```bash
FSC_STRICT_TESTS=1 pytest
```

（macOS は既定でファイル名の大小文字を区別しないため、ローカルでこれを立てると
`test_key_collision_within_location_is_reported` が失敗します。Linux の CI 向けの設定です。）

カバレッジ計測:

```bash
coverage run --source=. --omit="tests/*,.venv/*" -m pytest -q && coverage report -m
```

分岐カバレッジ付きで測る場合は `--branch` を足します。現状は行・分岐とも 99%
（未カバーは `if __name__ == "__main__"` の1行のみ）。

CLI テスト (`tests/test_cli.py`) は別プロセスで `main.py` を起動するため、
カバレッジには計上されません。`main()` の異常系は `tests/test_main.py` が
直接呼び出して確認しています。

テストは以下の観点をカバー:
- `comparator._classify`: 3拠点 2:1 / 1:2、4拠点 2:2 / 3:1、エラー優先判定、ハッシュ未計算時のサイズ判定
- `comparator.minority_hashes` / `minority_sizes`: 明確な過半数、タイ、全部違う、None 混在
- `comparator.compare`: エラー対象を欠落と分離、相対パスソート、dir差分、表示パスの決定
- `scanner`: 除外パターン（ファイル/ディレクトリ再帰）、シンボリックリンク非追跡、並列とシリアルの結果一致、チャンク境界を跨ぐハッシュ
- `scanner`: 読み取り失敗の記録（ハッシュ時／列挙時・ディレクトリ／リンク切れ）
- `scanner.plan_hash_targets`: `always`/`smart` の対象選定、更新日時の許容誤差、単独拠点ファイル
- `scanner`: 中断時にキュー済みタスクを待たないこと、大きいファイルの途中での中断
- `scanner.match_key`: NFC/NFD の同一視、大小文字、照合キーの衝突
- `config`: 拠点パス重複（末尾スラッシュ含む）、相対パス解決、各種バリデーション、CLI 上書き
- `reporter`: 出力できない文字（制御文字・不正UTF-8）でもレポートを落とさないこと
- `reporter`: 行あたり出力サイズと生成時ピークメモリの上限（肥大・メモリ回帰の防止）
- `reporter`: Windows ルート（UNC・ドライブレター）でのパス組み立て、出力の決定性
- `cli`: 実プロセスでの終了コード、各上書きオプション、不正な引数の拒否
- `main`: 設定エラー・中断・予期しない例外の終了コード、既定 config の探索順
- `utils`: 単位境界 (B/KB/MB/GB/TB/PB)、ロガーの二重初期化防止

## 設計方針

- 本ツールは**検出のみ**。修正・反映は人間が判断して実施。
- ロック中ファイル等の読み取り失敗はエラー扱いで継続実行し、レポートに記録。
  既定では再試行しない（`--retry N` で明示的に有効化する）。
- Ctrl+C は待ちキューを破棄して即座に戻る（実行中のハッシュ計算もチャンク単位で中断）。
- HTML レポートの行詳細は 1 つの JSON ブロックに集約し、クリック時に組み立てる。
  行ごとに詳細 HTML を埋め込むとレポートの大半がその重複で占められるため
  （実測: 1,000 ファイル × 3 拠点で 6.7MB のうち 87%）。
- 除外パターンはスキャン開始時に 1 本の正規表現へコンパイルする。エントリごとに
  `fnmatch` をパターン数だけ呼ぶと内部で `normcase` が 2 回走り、列挙フェーズの
  処理時間の 4 割を占めていた（実測: 20,000 ファイル・15 パターンで 222ms → 117ms）。
- 更新日時は **表示と判定で扱いを分けている**。レポートに出す日時は実行マシンの
  ローカル時刻だが、`hash_mode: smart` の一致判定はエポックからの `st_mtime_ns` で行う。
  拠点ごとにタイムゾーン設定の違うマシン経由でマウントしても判定が変わらない。
- `locations` は2件以上に対応。「欠落あり」「一部のみ存在」は過半数を基準にラベル分け。
- ハッシュ不一致セルの強調表示は最頻値（過半数）と異なる拠点のみ。タイの場合は全拠点を強調。
- いずれかの拠点で読み取り失敗があったファイルは **エラー対象ファイル** として独立カテゴリに分類し、欠落と区別。
